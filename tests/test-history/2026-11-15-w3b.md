## 설계와 다른 관찰

1. **`resends` 는 주기 재전송만 세지 않는다.** offer 쪽이 answer 를 못 받은 동안 상대의 `offer-request` 가 올 때마다 offer 를 다시 보낸다([protocol.md 3.2](../../docs/design/protocol.md#32-시그널별-처리) ①). 그래서 "offer 계속 버림 ②"에서 offer 쪽 `diag.resends` 가 8 이었다(주기 4 + 요청에 따른 4). [3.3](../../docs/design/protocol.md#33-재전송-기한-실패)의 "주기 재전송은 한 시도에 최대 4회"를 어기지 않는다. 요청에 따른 재전송에는 `SIGNAL_RESEND_MIN_GAP_MS` 가 걸리지 않는다(그 간격은 게이트웨이 프레임과 `SERVER_ERROR` 에만 정해져 있다). `get_status`·`join_room` 의 `details.resends` 를 읽는 쪽(W6, W9)이 "4 이하"를 가정하지 않아야 한다. 문서에 "주기와 요청에 따른 재전송을 합한 수"라고 적을지는 통합 담당이 정한다.
2. **같은 PC 에서는 기한까지 라이브러리가 스스로 실패하지 않았다.** 후보를 하나도 받지 못한 pc 는 15초에 `ice_state=checking`, `pc_state=connecting` 이었다. 실패는 모두 mesh 의 기한 타이머로 났다(PRE-RTC-07 과 같다).
3. **후보가 offer 보다 먼저 도착하면 answer 쪽 링크는 공개 STUN 응답보다 먼저 열린다.** 이 PC 에서 answer 쪽 srflx 는 link-open 뒤 37~51ms 에 나왔다. 공용 서버에서 순서가 바뀌는 경우(PRE-AWS-05)에는 "링크가 열린 뒤의 srflx" 경로가 저절로 지나간다는 뜻이다. 주입 없는 연결에서는 후보 묶음 대기(100ms) 때문에 srflx 가 늘 먼저다(W3a 관찰 3 과 같다).
4. **(나) 의 버림 규칙은 이 PC 에서 한 번도 적중하지 않는다.** 링크가 answer 쪽 첫 묶음(100ms)보다 먼저 열려 answer 쪽은 후보를 보내지 않는다. 판정은 "offer 쪽이 받은 후보 0건"으로 했다. 실제 NAT 처럼 연결이 늦으면 버림이 실제로 적중한다.

## 미실행과 이유

- `npm test`, `npm run build`, `npm run test:e2e`: 지시에 따라 공용 `dist` 를 쓰지 않았다.
- 실제 NAT·다른 PC(A-RTC-1), 실제 망에서의 "직접 연결 불가": PC 가 한 대다. 이 기록의 `ice` 실패는 프록시로 후보를 버린 주입이다.
- 공용 서버(AWS) 경유: 스택 `agent-chat-signaling` 이 없다(2026-11-15 확인. W2 진행 중).
- Linux·Windows, `wss://`, 장시간: 환경과 범위 밖.
- 32건을 넘는 후보 묶음을 나눠 보내는 경로: 이 PC 의 후보는 host 1건(+srflx 1건)뿐이다.

## 남은 위험

1. **L-W3A-06 의 1회 실패(후보 묶음 유실 뒤 10.4초, 재전송 3/3)는 원인 미확정이다.** 그 뒤 같은 주입을 145회(W3a 37, G1 7, 이 기록 101) 돌려 모두 3.0~3.4초였다. 라이브러리 로그를 켠 98회(P4 1, L-W3B-01 80, 05 15, 07 1, 08 1)에서도 느린 회가 없어 근거를 얻지 못했다. 후보를 3초 붙들었다 넣는 탐색(L-W3B-P3, 108회)도 400ms 를 넘지 않았다. 다시 나오면 `v-l11.mjs --only drop --drop-rounds <n> --native-log` 가 그 회의 mesh 사건과 라이브러리 로그(주소 가림)를 출력한다. 15초 기한은 그때도 지켰다.
2. `V-L11` 의 srflx 항목은 계획 문구대로는 이 PC 에서 계속 부분 검증이다. 보충 항목(공개 STUN + 후보 선도착)으로 경로는 지났다.
3. `[fail]` 의 판정은 같은 PC 의 주입에 기댄다. 실제 NAT 에서 라이브러리가 15초 전에 `failed` 를 내면 사유는 `ice`/`failed` 가 된다(단계는 같다). 시험은 그 경우를 `ice_timeout` 만 통과로 본다.
4. 색인(`tests/test-history/README.md`)은 통합 담당 소유라 고치지 않았다. 이 기록의 행을 더해야 한다.
