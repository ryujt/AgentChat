# 2026-11-15 W2: 공용 서버 (구현, 실제 배포, V-P1)

작업 묶음 W2([구현 계획](../../docs/design/implementation-plan.md#3-작업-묶음))의 구현·배포·검증 기록이다. 대상은 DynamoDB 저장소, 연결 관리 API 전송, Lambda 핸들러와 진입점, CloudFormation 템플릿, 배포·삭제·검증 스크립트, 저장소 계약 실행기다.

- 작업 ID: `2026-11-15-w2`
- 기준 상태: 브랜치 `main`, 커밋 `a82ed0e` + 커밋하지 않은 작업 트리(Gate 1 통합 뒤). 다른 묶음이 같은 작업 트리에서 동시에 일했다. 통합 담당 소유 파일은 고치지 않았다.
- 이 묶음이 만든 파일:
  - `src/signaling-aws/`: `index.ts`, `handler.ts`, `dynamo-store.ts`, `apigw-sink.ts`, `aws-clients.ts`, `config.ts`, `testing.ts`(시험 전용 대역), `handler.test.ts`, `dynamo-store.test.ts`, `apigw-sink.test.ts`, `config.test.ts`
  - `src/entry/lambda.ts`
  - `deployments/aws/`: `template.yaml`, `deploy.sh`, `destroy.sh`, `verify.mjs`, `test-store.mjs`
  - 앞선 시도(사용량 한도로 중단)가 남긴 `handler.ts`, `dynamo-store.ts`, `apigw-sink.ts`, `aws-clients.ts`, `config.ts` 는 읽고 설계와 맞춰 본 뒤 이어 썼다. 고친 곳은 `dynamo-store.ts` 의 타입 오류 하나(U-W2-01)다.
- 환경: macOS 27.2 arm64 한 대, Node v26.12.1, TypeScript 7.0.2, esbuild 0.28.2, `ws` 8.23.0, AWS CLI 2.39.0. AWS 는 서울(`ap-northeast-2`), 기본 프로필(계정 `<ACCOUNT>` 의 루트 자격 증명이었다), 호스팅 영역 `<ZONE>`. 인증서 ARN 은 스크래치 파일에서 읽어 넘겼고 이 문서와 저장소 파일에 적지 않았다.
- 빌드: `npx tsc -p tsconfig.json --outDir .work/w2/dist`. 프로세스를 띄우는 시험과 검증은 `AGENT_CHAT_DIST=.work/w2/dist`. 공용 `dist`, `npm run build`, `npm test` 는 쓰지 않았다. Lambda 번들은 `npm run build:lambda`(→ `build/lambda/index.mjs`).
- 참고한 이전 이력:
  - `2026-11-15-aws-apigw-websocket-probe`: 동작한 템플릿(라우트 응답 자원 제외), 인라인 코드는 CommonJS, 접근 로그 형식에 `$context.requestId` 필수(PRE-AWS-01), 스로틀 프레임(PRE-AWS-10)을 그대로 반영했다. 실행 역할의 연결 관리 권한은 탐색 때의 `POST` 만이 아니라 설계대로 `*/@connections/*`(GET·DELETE 포함)로 넓혔다.
  - `2026-11-15-w1`: 공용 서버에서 `wire-contract.mjs` 를 돌릴 때 `--flood-interval-ms 50` 이 필요하다는 메모를 따랐다(verify.mjs 의 기본값). "API Gateway 가 바이너리 프레임을 Lambda 에 넘기는지 재지 않았다"는 남은 확인을 P-W2-05 로 답했다.
  - `2026-11-15-gate1`: `touchPeer` 의 `seenSince` 조건(오래된 기록을 되살리지 않음)이 계약에 들어간 뒤의 상태로 구현했다.
- 원문 증거: 명령 출력은 `.work/w2/*.log`(버전 관리 밖), 탐색 스크립트는 스크래치(`<scratch>/impl/w2/`)에 있다. 7일 보존 대상이 아니다. CloudWatch 로그 그룹 두 개(`/agent-chat/agent-chat-signaling/function`, `/access`)는 보존 7일이다. 이 문서에 방 ID, 참가자 이름, key, SDP, 계정 ID, 인증서 ARN 은 없다.
- 실행 ID: 대역 `U-W2-NN`, 로컬 실물 `L-W2-NN`, 공용 서버 `P-W2-NN`, 문서·정적 확인 `D-W2-NN`. 시각은 KST.

## 설계와 다른 관찰

1. **바이너리 프레임은 공용 서버에서 연결 종료(1003)다.** 와이어 계약 시험의 그 항목이 공용 서버에서 실패하므로 `V-P1`("verify.mjs 전 항목 통과")을 채울 수 없다. 서버 코드로 고칠 수 없다. 제품 클라이언트는 바이너리를 보내지 않으므로 사용자 영향은 없다. 대안: (가) protocol.md 2.1 을 "바이너리 프레임은 받지 않는다. 자체 호스팅은 `BAD_MESSAGE`, 공용 서버는 1003 으로 닫는다"로 고치고 `wire-contract.mjs` 의 그 항목이 둘 다 받게 한다. (나) 자체 호스팅도 바이너리에 연결을 닫게 맞추고 시험이 "닫힘"을 기대하게 한다. 어느 쪽이든 W1 소유 파일과 protocol.md 를 바꾸는 결정이다.
2. **도메인 매핑은 스택 완료 뒤 약 3분 동안 HTTP 400 이다.** `deployment.md 2.10` 은 배포 직후 검증을 전제한다. verify.mjs 가 기한(기본 420초) 안에서 다시 시도하도록 만들었다(통과 기준은 그대로). 문서의 절차에 이 지연을 적을 필요가 있다.
3. **동시 입장·생성에서 "모두 거절"이 잦다.** 정원 하나 남은 방에 4개가 동시에 들어오면 20회 중 16회는 아무도 들어가지 못했다. 설계가 받아들인 대가이지만 빈도가 높다. 첫 입장의 `ROOM_FULL`·`ROOM_EXISTS` 는 사용자에게 실패로 보고되므로, 여러 참가자가 동시에 재접속하는 경우(`V-P7`)에 다시 볼 값이다.
4. **접근 로그 형식의 `$context.error.messageString`** 은 오류가 없을 때 따옴표 없는 `-` 를 내 줄이 JSON 으로 해석되지 않는다. 설계의 변수 목록을 그대로 썼다. `"error":"$context.error.message"` 로 바꾸면 항상 JSON 이 된다(설계 문서의 목록을 바꾸는 일이라 하지 않았다).
5. **배포 자격 증명이 계정 루트였다**(기본 프로필). 설계(2.6)는 배포자 권한을 최소로 적었다. 이번 실행의 결과에는 영향이 없다.

## 다른 묶음의 결함 (고치지 않고 보고)

- **`tests/wire/wire-client.mjs` 의 `openWire`(W1)**: 핸드셰이크가 거절됐을 때(`unexpected-response`) 응답만 비우고 요청 소켓을 닫지 않는다. 자체 호스팅 서버는 403 뒤 연결을 닫아 드러나지 않았고, 공용 서버(API Gateway)는 403 뒤에도 TLS 연결을 열어 두어 `wire-contract.mjs` 프로세스가 모든 시험을 끝낸 뒤에도 끝나지 않았다(P-W2-04, 10분 넘게 대기). 재현: `node --test-reporter=spec tests/wire/wire-contract.mjs --url wss://agent-chat.tools.camp --flood-interval-ms 50` → 요약 줄 뒤에 멈추고 `lsof -p <pid>` 에 대상 443 으로 `ESTABLISHED` 1개. 고치는 법: 그 처리기에서 `socket.terminate()`(또는 `_request.destroy()`)를 부른다. verify.mjs 는 `--test-force-exit` 로 비켜 갔다.

## 미실행과 이유

- `destroy.sh`, `V-P6`: 지시대로 실행하지 않았다(스택을 둔다).
- `V-P2`~`V-P5`, `V-P7`: G6 의 다음 단계(총괄 지시 범위 밖). P-W2-09 는 `V-P5` 가 아니다(표지 문자열 검색을 하지 않았다).
- `npm ci`: 여러 담당이 같은 작업 트리에서 일하는 중이라 `node_modules` 를 지우고 다시 까는 것을 피했다. `deploy.sh` 의 `--skip-install` 로 건너뛰었다(기본 동작은 설계대로 `npm ci` 를 한다).
- 경보(`--alarm-topic-arn`): 주제가 없어 만들지 않았다. 템플릿의 그 조건 분기는 실제로 돌려 보지 않았다.
- `--access-log off`, `--reserved-concurrency` 를 준 배포: 실행하지 않았다.
