## 남은 것

1. **사용자 결정 필요: 공용 서버 스로틀 값.** 초당 25·버스트 100 그대로다. `V-P7`(나)는 실패로 남는다(같은 서버의 다른 연결이 초당 35건이면 재접속, 45건부터 입장 실패). 올리면 남용 때의 비용 상한이 함께 오른다.
2. **재배포 필요(다음 단계):** SERVER-R1-01(`claimPeer`, `deletePeer` 의 `writtenAt`), SERVER-R1-03(연결 관리 API 재시도 없음, 스로틀 때 `SERVER_ERROR` 생략). 배포 뒤 `npm run test:store`(계약에 차지 2건이 늘었다)와 `verify.mjs`(갱신 배포라 이제 flood 를 건너뛴다)를 돌린다. `V-P7`(나)의 재실행은 부하 시험이라 총괄 결정대로 하지 않는다. 지금 공용 서버는 옛 코드다.
3. 총괄 결정 2-가의 비용: answer 쪽 시도가 열리기 전까지 주기마다 시그널 1건이 늘어난다(시도당 최대 4건). 스로틀 아래에서의 효과는 공용 서버에서 재지 않았다.
4. SERVER-R1-02 의 코드 수정(종료 표시 `closed` 와 조건식)은 하지 않았다. SERVER-R1-01 의 남는 틈: 판(`lastSeenAt`)이 서로 다른 실행에서 같은 ms 로 다시 쓰이는 경우, 차지와 등록 사이에 연결이 끝나 종료 통지가 등록보다 먼저 처리되는 경우(R1-02 와 같은 꼴).
5. BOUNDARY-R1-01 은 멈추고 알리는 방식이다. 사용자 키가 있는 등록은 Node 경로가 바뀌면 손으로 고쳐야 한다(R1-02 로 경로가 바뀌는 일은 줄었다). Claude Code 등록(`~/.claude.json`)에는 이런 서버별 권한 키가 없다고 보고 손대지 않았다 **[추론, 미확인]**. 버전 관리 도구의 셸 스크립트 shim 은 여전히 실경로로 등록된다.
6. **`a-rtc` 교대 중 간헐 `ice/failed`(L-R1-16, 다시 입장 160회 중 1회, 원인 미상).** 다음 실행부터 `--keep-home` 으로 돌려 실패 회차의 `mesh` 로그(`link.attempt_end`, `link.attempt_swap`, `pc_state`)를 남긴다. 설치 e2e 의 "네이티브 모듈 못 불러옴" 시험은 `TMPDIR` 조상에 `node_modules` 가 없다고 가정한다(L-R1-15).
7. Gate 3 의 남은 것 2~5 그대로(`V-S1`·`V-S2`·`V-L9`·`V-P4`·`V-P6`·`V-I*` 미실행, `V-L11` srflx 부분 검증, G1 남은 것, 고친 설계 문서의 독립 검토).
