# 2026-11-15 W7: 진단 로그 (`src/diagnostics`)

작업 묶음 W7([구현 계획](../../docs/design/implementation-plan.md#3-작업-묶음))의 파일 로거, stdout 로거, 허용 필드 필터, 보존 정리를 만들고 `V-U6`([검증 계획](../../docs/design/verification-plan.md))을 실행한 기록이다.

- 작업 ID: `2026-11-15-w7`
- 대상: `src/diagnostics/fields.ts`, `retention.ts`, `file-logger.ts`, `stdout-logger.ts`, `index.ts`, `testing.ts` 와 시험 다섯 파일(`fields.test.ts`, `retention.test.ts`, `file-logger.test.ts`, `stdout-logger.test.ts`, `index.test.ts`). `log-port.ts`, `contract.ts` 는 고치지 않았다.
- 기준 상태: 브랜치 `main`, 커밋 `a82ed0e` + 작업 트리(미커밋). 다른 묶음이 같은 작업 트리에서 동시에 작업 중이었다.
- 환경: macOS(Darwin 27.2.0) arm64 한 대, Node v26.12.1, TypeScript 7.0.2. 빌드 출력은 `.work/w7/dist`.
- 참고한 이전 이력: `2026-11-15-w0-contracts`(계약과 `V-U8` 정적 검사), `2026-11-15-pre-implementation-assumptions` 의 PRE-MCP-06(stdout 에는 MCP 메시지만), PRE-MCP-10·11(stderr `error` 리스너). 반영: 파일 로거는 stdout 에 쓰지 않고, stderr 의 `error` 를 받아 둔다(W7-06 의 실제 프로세스 시험).

- **대역**: `fields.test.ts`, `retention.test.ts`, `file-logger.test.ts`, `stdout-logger.test.ts`. 가짜 시계, 메모리 파일, 가짜 stderr·출력 자리.

## 미실행 항목과 이유

- `npm test`(공용 `dist`) 전체: 여러 묶음이 동시에 작업 중이라 묶음별 출력 폴더만 쓴다. 통합 담당이 실행한다.
- 시간 파일 20MB 상한을 **기본값으로** 채우는 시험: 줄을 20MB 만큼 만들어야 해서 작은 상한(400바이트)으로 같은 경로를 봤다. 기본값 자체는 상수(`MAX_HOUR_FILE_BYTES`)로만 확인된다.
- Lambda 런타임의 `console.log` → CloudWatch Logs: 로컬에서는 `console.log` 가 한 인자의 JSON 문자열로 불리는 것까지만 봤다. 실제 형식은 `V-P1` 범위다.
- stdout·stderr 가 닫힌 상태(`EPIPE`)에서의 실제 프로세스 동작: `error` 리스너를 붙이고 떼는 것만 봤다.
- Windows 의 권한 비트: 대상 환경이 아니다.
