## 만든 것과 정한 것

- **시험에서 `npm ci` 와 빌드를 대신하는 방법.** 설치 시험은 `PATH` 앞에 둔 가짜 `npm`(받은 인자만 적고 끝난다)과 미리 만든 빌드 결과(`AGENT_CHAT_DIST`, 기본 `<저장소>/dist`)로 대신한다. 실제 `npm ci` 는 네트워크와 수십 초가 들어 시험마다 돌리지 않는다. 네이티브 모듈 확인(4단계)은 `node_modules` 를 링크해 **실제로** 한다. 제품 코드에 시험용 분기는 없다.
- **시험이 실제 홈에 닿지 않게 한 방법.** `HOME` 은 공백이 든 임시 폴더다. `PATH` 는 시험용 폴더와 `/usr/bin`, `/bin` 뿐이라 이 PC 의 실제 `claude`·`codex` 가 없다. 환경은 새로 만든다(세션의 환경 변수를 물려주지 않는다). 가짜 호스트 CLI 는 `HOME` 에 표식 파일이 있을 때만 쓴다.
- **MCP 진입점.** `src/entry/mcp.ts` 는 다른 묶음이 조립한다. 설치 시험은 `<app>/dist/entry/mcp.js` 자리에 MCP SDK 로 만든 가짜 서버를 복사해 둔다. `doctor` 는 그것을 등록된 명령 그대로 띄운다.

**A-MCP-10 의 결론**

- 비교 목록([architecture.md 3.13](../../docs/design/architecture.md#313-setup))의 키는 이 PC 의 Claude Code 2.1.325 와 Codex 0.169.0 에서 이름이 맞다. `permissions`, `approval_policy`, `sandbox_mode` 는 이 PC 의 파일에 없어 여전히 문서 기준이다.
- `codex mcp list --json` 은 서버별 명령·인자·환경 변수를 낸다. (가)를 그 출력으로 비교할 수 있다.

**관찰** (목록을 정하는 통합 담당에게 넘긴다)

1. `~/.claude.json` 의 `projects.*` 에 `mcpContextUris` 가 있다. 이름에 mcp 가 든다. 비교 도구에는 이미 더했다(`CLAUDE_PROJECT_KEYS`). 설계 표에 더할지 정해 달라. 호스트가 이 키를 스스로 채우는지는 보지 못했다(17개 모두 빈 배열).
2. `codex mcp list --json` 에는 `enabled_tools`, `disabled_tools` 가 없다(`get --json` 에는 있다). 승인 모드 키(`default_tools_approval_mode`)는 둘 다에 없다. 그래서 다른 서버의 승인 관련 키가 바뀌어도 (가)로는 보이지 않는다. 비교 도구는 `mcp_servers.*` 표(`agent-chat` 제외)의 모든 키를 줄 단위로도 읽어 비교한다.
3. `codex mcp list --json` 에는 설정 파일에 없는 서버(플러그인·앱이 넣는 것)도 나온다. 그 환경에 앱 버전 같은 값이 들어 있어, 두 사본 사이에 Codex 앱이 갱신되면 설치와 무관하게 다르다고 나올 수 있다. `auth_status` 는 설정이 아니라 상태다. 지금은 항목 전체를 비교한다.
4. 호스트가 `projects.*` 항목에 빈 기본값(`mcpServers: {}`)을 채우는 경우가 있다(17개 중 1개에만 키가 없다). 그래서 비교 도구는 **비어 있거나 거짓인 값을 키가 없는 것과 같게** 본다. 권한을 준 것이 없다는 뜻이 같기 때문이다. 값이 생기거나 없어지는 변화는 그대로 잡는다(자체 시험에 있다).
5. Codex 설정의 `[plugins.*] enabled` 는 목록에 없다. 플러그인이 MCP 서버를 더할 수 있다(3번). 목록에 넣을지 정해 달라. 비교 도구에는 넣지 않았다.

| 서버 주소를 등록 환경에 넣음 | registration, setup |

## 한계와 미실행

| 항목 | 상태 | 이유 |
|---|---|---|
| `V-S1` (이 PC 의 실제 홈 설치와 전후 비교) | **미실행** | 지시: 지금 실제 홈에 설치하지 않는다. 총괄이 `node tests/e2e/install/v-s1.mjs --yes` 로 실행한다 |
| `V-S2` (등록된 명령 그대로 공용 서버를 거친 통신) | **미실행** | `V-S1`, 공용 서버 배포, 실제 MCP 진입점이 선행이다. `node tests/e2e/install/v-s2.mjs` |
| `V-I1` (에이전트 주도 설치) | 미실행 | 사람과 실제 세션, GitHub 푸시가 필요하다 |
| 실제 `claude mcp add`·`remove`, `codex mcp add`·`remove` | 미실행 | 지시: 등록·제거 금지. 형식은 도움말(R-02, R-03)과 조회 출력(R-05, R-06)으로만 맞췄다 |
| `claude mcp get` 의 `Environment:` 아래 줄 형식 | **미확인(가정)** | 이 PC 에 환경 변수가 든 등록이 없고 등록을 만들 수 없었다. `    KEY=value` 로 가정했다. 틀리면 다시 설치할 때마다 등록을 지우고 다시 만들며 이름이 바뀐다. `V-S1` 의 S1-05(다시 실행해도 등록이 같다)가 잡는다 |

| Channels 판정표 6·7행을 프로세스 수준에서 | 미실행 | 관리형 설정 파일이 OS 의 고정 위치(`/Library/Application Support/ClaudeCode/`)에 있어야 한다. 단위 시험이 임시 파일을 같은 읽기 함수로 읽어 본다 |
| 설치 시험 안의 실제 `npm ci`·`npm run build` | 미실행 | 가짜 `npm` 으로 대신했다(위 "만든 것과 정한 것"). 실제 설치와 빌드는 `2026-11-15-w0-contracts` 의 W0-15, W0-16 에 있다 |

## 후속

- `V-S1` 을 실행하기 전에 통합 담당이 "관찰" 1~5 를 보고 비교 목록을 확정한다. 실행한 뒤에는 목록을 줄이지 않는다.
- `V-S1` 의 첫 실행에서 `claude mcp get` 의 환경 변수 줄 형식과 `codex mcp add` 가 쓰는 TOML 의 모양을 확인한다. 가정과 다르면 `src/setup/registration.ts`(읽기), `src/setup/codex-config.ts`(표 찾기)와 가짜 CLI 를 함께 고친다.
- 실제 MCP 진입점이 조립되면 `doctor` 를 그것으로 다시 돌린다(`V-S2` 의 S2-09).
