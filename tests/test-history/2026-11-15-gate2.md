묶음 W2(공용 서버), W3b(연결 통합 재실행), W6b(`V-U9`·`V-L12` 재실행)의 산출물을 한 작업 트리에서 합쳐 빌드하고, 담당들이 낸 관찰·결함·결정 요청을 판단해 계약·구현·설계 문서에 반영한 기록이다([구현 계획](../../docs/design/implementation-plan.md)의 G2).

- 작업 ID: `2026-11-15-gate2`
- 기준 상태: 브랜치 `main`, 커밋 `a82ed0e` + 커밋하지 않은 작업 트리(W0~W8, G1, W2, W3b, W6b 의 산출물 전체). 실행하는 동안 다른 담당은 일하지 않았다.

- 참고한 이전 이력: `2026-11-15-gate1`(형식과 재실행 목록), `-w2`(P-W2-05 바이너리 실측, 와이어 시험이 끝나지 않던 실행 P-W2-04), `-w3b`(관찰 1~4), `-w6b`, `-w1`(F-13).
  - 반영: G1 이 다시 돌린 프로세스 시험 전부를 공용 `dist` 로 다시 돌렸다. 바꾼 와이어 계약(바이너리 프레임)은 자체 호스팅과 공용 서버 양쪽에서 확인했다.

## 미실행 항목과 이유

- `deploy.sh` 재실행: 실제 AWS 자원을 바꾸는 일이고 이번 역할의 지시 범위 밖이다. 다시 돌리면 고친 접근 로그 형식도 함께 반영된다.
- `npm run test:e2e`: 실행기 `tests/e2e/run.mjs` 가 아직 없다(W9).
- `V-L2`~`V-L9`, `V-L7`(나), `V-P2`~`V-P7`, `V-S*`, `V-I*`: 조립(`src/entry/mcp.ts`)·시나리오가 없거나 실제 호스트·다른 PC 가 필요하다.
- 묶음마다의 변이 점검 전수, 고친 설계 문서의 독립 재검토.

## 남은 것

1. **`V-P1` 을 통과로 닫으려면 `deploy.sh` 를 한 번 더 돌려 exit 0 을 봐야 한다.** 그때 접근 로그 형식 수정이 배포되므로, 접근 로그 한 줄이 JSON 으로 읽히는지도 함께 본다(`V-P5` 의 전제).
2. `V-L11` srflx 항목은 이 PC 에서 부분 검증으로 남는다(다른 망 필요).
3. W3a 1차 실행의 1회 실패(10.4초)는 원인 미상. 이번 L-G2-09 의 `[drop]` 도 3.0~3.2초였다.
4. 동시 입장·생성의 "모두 거절" 빈도(공용 서버 4/10, 7/10). `V-P7` 에서 사용자 영향(재시도 안내)을 본다.
5. G1 의 남은 것 1~7 은 그대로다(`AGENT_CHAT_HOME` 등록, 예산 초과 종료 시간, `NOT_JOINED` 복구 지연, `leave` 정리 기한 등).
6. 배포 자격 증명이 계정 루트였다(W2). 다음 배포 전에 최소 권한 사용자로 바꾸는 것이 좋다.
