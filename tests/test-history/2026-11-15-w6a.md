# 2026-11-15 W6 방 조율: room-session 구현과 단위 검증

작업 묶음 W6([구현 계획](../../docs/design/implementation-plan.md#3-작업-묶음))의 첫 단계 기록이다. `src/room-session/**`(계약 파일 제외)를 만들고 `V-U9` 를 실행했다. `tests/e2e/room/` 의 하네스와 `V-L12` 스크립트는 써 두고 동작 점검만 했다. `V-L12` 의 판정은 다음 단계 담당의 실행으로 한다.

- 작업 ID: `2026-11-15-w6a`
- 대상: `src/room-session/` 의 구현 파일 10개(`index.ts`, `session.ts`, `room.ts`, `signal-gate.ts`, `mesh-keeper.ts`, `p2p-session.ts`, `chat-delivery.ts`, `participants.ts`, `events.ts`, `views.ts`. `index.ts` 는 내보내기만 한다), 시험 지원 `testing.ts`, 시험 파일 8개(`*.test.ts`), `tests/e2e/room/`(`peer.mjs`, `harness.mjs`, `v-l12.mjs`)
- 기준 상태: 브랜치 `main`, 커밋 `a82ed0e` + 작업 트리. 실행하는 동안 다른 묶음(W1~W5, W7, W8)이 같은 작업 트리에서 파일을 쓰고 있었다. 빌드는 그때의 작업 트리 전체를 컴파일한 것이다.
- 환경: macOS 27.2.1 arm64 한 대, Node v26.12.1. 빌드 `npx tsc -p tsconfig.json --outDir .work/w6a/dist`.
- 검증 수준: 대역(`U-`)과 로컬 실물(`L-`). 실제 NAT, 다른 PC, 공용 서버, 실제 에이전트 호스트는 쓰지 않았다.
- 참고한 이전 이력:
  - `2026-11-15-w0-contracts`: 묶음별 빌드 폴더와 `AGENT_CHAT_DIST`(W0-17), `protocol` 의 보내기 전 검증(`encodeP2PFrame`, `packStateFrames`). 반영: 같은 빌드 방식을 썼고, 프레임은 모두 그 두 함수로 만든다.
  - `2026-11-15-pre-implementation-assumptions`: PRE-RTC-03·04(같은 PC 에서 링크가 host 후보로 먼저 열린다), PRE-AWS-04·05(공용 서버에서 `offer` 가 `joined` 보다 먼저 올 수 있다). 반영: `joined` 전 시그널 보관을 단위 시험과 프록시 주입으로 봤다. 공용 서버에서의 순서 자체는 다시 실측하지 않았다.
  - `2026-11-15-design-review`: 문서 검토 기록이다. 실행 조건에는 쓰지 않았다. `V-U9` 표 1~11번 기준은 그 검토에서 고정된 것을 그대로 썼다.
- 원문 증거: 명령 출력은 세션 임시 폴더(`<scratch>` = 세션 임시 폴더의 `impl/w6a/`)에 있고 보존 대상이 아니다. 재현에 필요한 명령·조건·판정은 이 문서에 적었다. 출력에 방 ID, 채팅 본문, SDP 는 없다.
- 시각은 KST 다. "경"은 파일 수정 시각에서 옮긴 것이다(실행 때 시각을 찍지 않았다).

| 주입의 증거 | 버린 시그널 103건. 8번 본 `get_status` 모두에서 `anna`–`bert` 링크가 `open` 이 아니었고 둘 다 `cara` 와는 `open` |
| (1) 경과 시간 | `anna` 180001ms(실제 180003ms, 차이 −2ms), `cara` 180003ms(실제 180004ms, 차이 −1ms) |
| (2) `bert` 의 주장 24건이 `anna` 의 복제본에 들어온 시간 | 빠진 것 0건, 가장 늦은 것 23231ms(기준 45초) |
| (3) `bert` 의 마지막 `presence` | 27ms 안에 들어와 있었다 |
| (4) 180초 동안 `anna`–`cara` 의 `state.resync` | 6회(`ping_mismatch`, `reply`). `gap_ms` 는 모두 30000 |
| (5) `state_diverged` | 사건·로그 0건, 경고 0건 |
| (6) `stop` 이 `anna` 의 복제본에 들어온 시간 | 3ms(`cara` 의 스냅샷으로) |
| (7) 로그 | `cara` 에 `state.resync{cause: stop, peer: anna}`, 그 뒤 `anna` 에 `cara` 의 스냅샷 병합(applied 2) |
| (8) `bert` 의 채팅 | `delivered=[cara]`, `anna` 는 `not_connected`. `anna` 의 수신함 0건, `cara` 1건 |
| (9) 끝났을 때의 지문 | 셋이 같았다(기록 30건) |

이 값은 같은 PC, host 후보만 쓴 구성의 것이다. 실제 망의 시간으로 보고하지 않는다.

### U-RS-MUT 의 변이

깨뜨린 규칙마다 시험이 1건 이상 실패(또는 기한 초과)했다.

| 파일 | 변이 |

## 관찰과 다음에 확인할 것

- 가짜 mesh 는 `link-open` 을 양쪽에 먼저 낸 뒤 프레임을 전달한다. 실물 mesh 에서도 첫 동기화가 "동시에 시작한 교환"이 된다는 것은 L-RS-01·05 에서 봤다(입장이 되고 지문이 같았다). 프레임이 `link-open` 보다 먼저 올 수 있는지는 mesh 의 시험(`V-U11`)이 볼 일이다.
- L-RS-05 에서 `bert` 의 주장이 `anna` 에 닿는 데 가장 늦은 것이 23.2초였다. 설계의 계산값(최대 약 35초) 안이다.
- 8번·11번은 shared-state 실물이 `adoptElapsed` 를 규칙대로 구현했을 때만 뜻이 있다. 가짜 복제본으로 돌린 예비 실행은 판정에 쓰지 않았다.
- 변이 확인은 `<scratch>` 의 사본에서 했다. 사본과 저장소 소스가 같다는 것은 사본을 만든 직후의 기준 실행(tests 142, pass 142)으로만 확인했다.
