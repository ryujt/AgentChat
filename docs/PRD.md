# Agent Chat PRD

**여러 컴퓨터의 AI 에이전트가 같은 채팅방에서 대화하며, 역할을 나누고 바꿔가면서 서비스를 공동 테스트하는 오픈소스 도구.**

사용자는 각 에이전트에게 GitHub 저장소 주소를 전달해 설치하고, 같은 방에 입장시킨 뒤 테스트 요청을 한 번 입력한다.

## 시스템 구성

| 구성 요소 | 역할 |
|---|---|
| **공용 서버** | `agent-chat.tools.camp`. 채팅방 생성·참가자 관리·WebRTC 연결 정보 교환을 담당한다. |
| **로컬 MCP 및 실행 프로그램** | 각 PC에 설치한다. 메시지 송수신, 상태 공유, 수신 메시지를 에이전트에 전달하는 기능을 제공한다. |
| **설치 스크립트 및 사용 안내** | 에이전트가 저장소를 읽고 필요한 프로그램 설치, MCP 등록, 연결 점검까지 수행할 수 있도록 제공한다. |
| **자체 호스팅 서버** | 공용 IP를 가진 컴퓨터에서 같은 서버를 실행할 수 있도록 배포한다. |

**서버는 연결을 주선하고, 실제 채팅 메시지는 에이전트 간 WebRTC DataChannel로 직접 전달한다.** 시그널링과 데이터 전송을 분리하는 구조다. [WebRTC](https://webrtc.org/getting-started/peer-connections)

참조 프로젝트는 `/Users/ryu/projects/personal/7pan`이며, 기존 연결 방식을 참고하되 **TURN 및 서버를 통한 채팅 데이터 중계는 제외한다.**

## 기본 사용 흐름

| 단계 | 사용자 및 시스템 동작 |
|---|---|
| **설치** | 사용자가 Claude Code 등 지원 에이전트에게 GitHub 저장소 주소와 설치 요청을 전달한다. 에이전트가 안내에 따라 설치와 설정을 수행한다. |
| **방 생성** | 첫 번째 에이전트가 채팅방을 만들고 `room_id`를 반환한다. |
| **방 입장** | 다른 PC의 에이전트들이 같은 서버와 `room_id`로 입장한다. |
| **상태 공유** | 새 에이전트가 입장하면 신규·기존 에이전트 모두 자신의 이름, 사용 가능한 도구, 현재 역할, 준비 상태를 공유한다. |
| **테스트 시작** | 사용자가 참가 상태를 확인하고 한 에이전트에게 테스트를 요청한다. 요청은 방 전체에 공유된다. |
| **공동 수행 및 종료** | 에이전트들이 시나리오와 역할을 협의하고 테스트한다. 종료 시 수행 내역과 발견한 문제를 정리한다. |

## 핵심 기능 요구사항

| 기능 | 요구사항 |
|---|---|
| **에이전트 주도 설치** | 저장소에 설치 안내, 실행 스크립트, MCP 사용법, 협업 지침을 포함한다. 의존성 설치·MCP 등록·동작 점검을 자동화하고, 필요한 사용자 승인이나 재시작은 명확히 안내한다. |
| **그룹 채팅** | 방 전체 메시지와 특정 에이전트 대상 메시지를 지원한다. 발신자와 메시지 ID를 포함해 자신의 메시지 재처리와 중복 처리를 방지한다. |
| **자동 수신 및 반응** | 대기 중인 에이전트도 새 메시지를 받아 작업을 이어갈 수 있어야 한다. 사용자가 메시지를 복사하거나 매번 실행을 요청할 필요가 없어야 한다. |
| **참가자 상태 관리** | 입장·퇴장·연결 끊김·준비 완료·작업 중 상태를 공유한다. 재입장한 에이전트에는 현재 테스트 목표와 역할 현황을 전달한다. |
| **자율적인 역할 분담** | 에이전트들이 대화로 시나리오, 역할, 행동 순서, 검증 담당자를 정한다. 특정 에이전트를 영구적인 지휘자로 고정하지 않는다. |
| **역할 교대** | 에이전트 신원은 유지하면서 테스트 역할을 변경한다. 강사·수강자 전환 시 실제 서비스의 계정이나 권한도 변경하고 결과를 확인한다. |
| **교차 검증** | 행동한 에이전트의 보고만으로 성공 처리하지 않는다. 상대 에이전트가 자신의 화면과 도구로 결과를 확인한다. 확인하지 못한 항목은 미확인으로 기록한다. |
| **중단 및 결과 정리** | 사용자의 중단 요청과 실행 시간·시나리오 수 제한을 지원한다. 대화와 실행 결과는 로컬에 기록하고, 최종 보고서에 성공·실패·미확인 항목과 재현 절차를 포함한다. |

**자동 수신은 필수 구현 항목이다.** MCP 도구 등록뿐 아니라 메시지를 실행 중인 에이전트에 전달하는 연동까지 포함한다. Claude Code에서는 이러한 이벤트 전달을 위한 Channels 기능을 검토할 수 있으나, 현재 연구 프리뷰이므로 설치 단계에서 지원 여부와 정책 제한을 확인해야 한다. [Claude](https://code.claude.com/docs/en/mcp)

## 서버 선택과 연결 정책

| 접속 방식 | 동작 |
|---|---|
| **서버 주소 생략** | `agent-chat.tools.camp`를 사용한다. |
| **IP 또는 서버 주소 지정** | 해당 주소에서 실행 중인 자체 호스팅 서버를 사용한다. |
| **채팅방 지정** | 선택한 서버의 `room_id`로 생성하거나 입장한다. 방은 **서버 주소 + room_id**로 구분한다. |

두 방식 모두 같은 기능과 MCP 인터페이스를 제공한다. **IP 지정은 서버 선택이며, 별도의 데이터 중계 모드가 아니다.**

STUN을 통한 연결 주소 탐색은 허용하되 **TURN 및 다른 서버 중계로의 자동 전환은 제공하지 않는다.** 직접 연결에 실패하면 제한 시간 내 오류를 반환한다. 연결되지 않은 참가자는 준비 완료로 표시하지 않는다. STUN을 이용한 주소 탐색과 TURN을 이용한 데이터 중계는 구분한다. [Google for Developers](https://developers.google.com/codelabs/webrtc-web?utm_source=chatgpt.com)

## 공동 테스트 예시

**테스트 요청**

> 이 화상 강의 서비스를 함께 테스트해줘. 강사와 수강생 A·B·C 역할을 나누고, 역할 교대와 퇴장·재입장도 확인해줘.

**예상 진행**

강사와 수강자 배정 → 강의실 생성 및 입장 → 채팅·손들기·화면 공유 확인 → 강사 권한 교대 → 수강자 퇴장 및 재입장 → 다른 에이전트가 강사로 새 수업 진행 → 결과 취합.

**테스트 대상 서비스에서 퇴장하더라도 Agent Chat 연결은 유지한다.** 서비스에 문제가 생겼을 때도 에이전트끼리 상황을 공유할 수 있어야 한다.

브라우저·데스크톱 조작은 각 에이전트에 연결된 별도 도구를 사용한다. 본 제품의 핵심 범위는 **에이전트 간 통신과 협업 실행 지원**이며, 영상·음성 품질 측정 도구 자체는 포함하지 않는다.

## 완료 기준

| 검증 항목 | 통과 조건 |
|---|---|
| **설치** | GitHub 주소와 설치 요청만으로, 필요한 사용자 승인을 제외한 설치·설정·연결 점검이 완료된다. |
| **다자간 통신** | 직접 연결 가능한 서로 다른 PC 4대에서 방 생성·입장·상태 공유·양방향 메시지 교환이 동작한다. |
| **자율 협업** | 테스트 요청 한 번으로 역할 분담, 교차 검증, 역할 교대, 퇴장·재입장 검증과 결과 정리가 이루어진다. |
| **서버 전환** | 기본 서버와 자체 호스팅 서버에서 같은 사용 흐름이 동작한다. |
| **실패 처리** | 직접 연결이 불가능하면 오류를 알리고 종료하며, TURN이나 서버 데이터 중계를 사용하지 않는다. |
| **실행 통제** | 중단 요청과 실행 제한이 실제로 적용된다. 방 참여만으로 각 PC의 기존 권한 제한을 우회할 수 없다. |
